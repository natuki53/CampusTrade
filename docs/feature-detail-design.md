# CampusTrade 機能詳細設計書

## 1. 目的

本書は CampusTrade の主要機能について、処理手順、入力、出力、検証、権限制御を定義する。Controller、Service、Repository を実装する際の判断基準として使用する。

## 2. 共通仕様

### 2.1 ログインユーザー取得

認証が必要な処理では、Spring Security の認証情報から現在のユーザーを取得する。Service 層では、必要に応じて DB 上の `users` を取得し、権限と本人確認を行う。

### 2.2 権限チェック

| 操作 | チェック内容 |
|---|---|
| 商品編集 | ログインユーザーが `seller_id` と一致すること |
| 商品非表示 | ログインユーザーが `seller_id` と一致すること |
| 購入申し込み | ログイン済み、商品が `OPEN`、自分の商品ではないこと |
| 取引メッセージ | 出品者、購入者、管理者のいずれかであること |
| 購入者取引詳細 | ログインユーザーが `buyer_id` と一致すること、または管理者であること |
| 出品者取引詳細 | ログインユーザーが `seller_id` と一致すること、または管理者であること |
| 管理者操作 | `role = ADMIN` であること |

### 2.3 商品表示条件

一般ユーザー向けの商品一覧では、以下を満たす商品だけを表示する。

```sql
trade_status = 'OPEN'
AND moderation_status = 'ACTIVE'
AND deleted_at IS NULL
```

管理者画面では、禁止表示や論理削除済みの商品も確認できる。

## 3. ユーザー登録

### 3.1 概要

学生番号、パスワード、ニックネームを登録し、一般学生ユーザーを作成する。

### 3.2 入力

| 項目 | 必須 | ルール |
|---|---|---|
| 学生番号 | 必須 | 32文字以内、重複不可 |
| パスワード | 必須 | ハッシュ化して保存 |
| ニックネーム | 必須 | 50文字以内 |

### 3.3 処理手順

1. 入力値を受け取る。
2. 必須チェックと文字数チェックを行う。
3. 学生番号の重複を確認する。
4. パスワードをハッシュ化する。
5. `role = STUDENT` で `users` に登録する。
6. ログイン画面へ遷移する。

### 3.4 異常系

| ケース | 対応 |
|---|---|
| 学生番号が重複 | 会員登録画面にエラー表示 |
| 必須項目未入力 | 会員登録画面にエラー表示 |

## 4. ログイン・ログアウト

### 4.1 概要

学生番号とパスワードでログインし、ログイン後はトップ画面へ遷移する。

### 4.2 処理手順

1. `student_number` と `password` を受け取る。
2. Spring Security がユーザーを検索する。
3. パスワード照合に成功した場合はログイン状態にする。
4. トップ画面へ遷移する。

### 4.3 異常系

| ケース | 対応 |
|---|---|
| 認証失敗 | ログイン画面にエラー表示 |
| ログアウト成功 | ログイン画面に完了メッセージ表示 |

## 5. 商品一覧・検索

### 5.1 概要

トップ画面と商品検索結果画面で、出品中の商品を表示する。

### 5.2 入力

| 項目 | 必須 | 説明 |
|---|---|---|
| `keyword` | 任意 | 商品名・説明を部分一致検索 |
| `categoryId` | 任意 | カテゴリで絞り込み |
| `onSaleOnly` | 任意 | 販売中のみ表示 |

### 5.3 処理手順

1. 検索条件を受け取る。
2. 一般表示条件を付与する。
3. キーワードがある場合は商品名・説明を検索する。
4. カテゴリがある場合はカテゴリで絞り込む。
5. 作成日時の降順で並べる。
6. 代表画像と商品情報を画面へ返す。

## 6. 商品詳細

### 6.1 概要

商品情報、画像、商品コメント、取引状態に応じた操作ボタンを表示する。取引メッセージは商品詳細には表示せず、購入者取引詳細または出品者取引詳細に表示する。

### 6.2 処理手順

1. 商品IDで `products` を取得する。
2. 商品が存在しない場合は404とする。
3. 一般ユーザーの場合、禁止表示または論理削除済みの商品は表示しない。
4. 商品画像を `display_order ASC` で取得する。
5. 商品コメントを `created_at ASC` で取得する。
6. ログイン状態と権限に応じて操作ボタンを切り替える。

### 6.3 表示制御

| 条件 | 表示 |
|---|---|
| 未ログイン | 商品情報、コメント、ログイン導線 |
| 他人の商品かつ `OPEN` | 購入申し込みボタン |
| 自分の商品かつ `OPEN` | 編集、非表示ボタン |
| 出品者または購入者かつ `LOCKED` | 取引詳細への導線 |
| `CLOSED` | 取引完了表示 |

## 7. 商品出品

### 7.1 概要

ログイン済みユーザーが商品情報と画像を登録する。

### 7.2 入力

| 項目 | 必須 | ルール |
|---|---|---|
| 商品名 | 必須 | 100文字以内 |
| 説明 | 必須 | 空不可 |
| 価格 | 必須 | 0円以上 |
| カテゴリ | 必須 | 存在するカテゴリ |
| 商品状態 | 必須 | 50文字以内 |
| 商品画像 | 任意 | 最大5枚、1枚5MBまで、JPEG/PNG/WebP |

### 7.3 処理手順

1. 入力値を受け取る。
2. 商品情報の入力チェックを行う。
3. 画像の枚数、サイズ、形式をチェックする。
4. `products` に商品を登録する。
5. 画像がある場合は `product_images` に登録する。
6. 先頭画像を代表画像にする。
7. 商品詳細画面へ遷移する。

### 7.4 登録時の初期値

| 項目 | 値 |
|---|---|
| `seller_id` | ログインユーザーID |
| `buyer_id` | `NULL` |
| `trade_status` | `OPEN` |
| `moderation_status` | `ACTIVE` |
| `deleted_at` | `NULL` |

## 8. 商品編集

### 8.1 概要

出品者本人が `OPEN` の商品情報を編集する。

### 8.2 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. 出品者本人でない場合は403とする。
4. `trade_status` が `OPEN` でない場合は編集不可とする。
5. 入力チェックを行う。
6. 商品情報を更新する。
7. 画像変更がある場合は画像を更新する。
8. 商品詳細画面へ遷移する。

## 9. 商品非表示

### 9.1 概要

出品者本人が商品を一覧に表示しない状態にする。履歴保持のため物理削除は行わない。

### 9.2 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. 出品者本人でない場合は403とする。
4. `deleted_at` に現在日時を設定する。
5. マイページへ遷移する。

## 10. 購入申し込み

### 10.1 概要

ログイン済みユーザーが `OPEN` の商品に購入申し込みを行う。

### 10.2 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. 未ログインの場合はログイン画面へ遷移する。
4. 自分の商品である場合はエラーにする。
5. `trade_status` が `OPEN` でない場合はエラーにする。
6. `moderation_status` が `ACTIVE` でない場合はエラーにする。
7. `deleted_at` が `NULL` でない場合はエラーにする。
8. `buyer_id` にログインユーザーIDを設定する。
9. `trade_status` を `LOCKED` に変更する。
10. 購入者取引詳細へ遷移する。

### 10.3 排他制御

同じ商品に対する同時購入申し込みを防ぐため、更新時に `trade_status = OPEN` を条件に含める。更新件数が0件の場合は、購入不可として商品詳細画面に戻す。

## 11. 取引キャンセル

### 11.1 概要

`LOCKED` の取引をキャンセルし、商品を再び出品中に戻す。

### 11.2 実行可能ユーザー

- 出品者
- 購入者
- 管理者

### 11.3 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. 実行者が関係者でない場合は403とする。
4. `trade_status` が `LOCKED` でない場合はエラーにする。
5. `buyer_id` を `NULL` にする。
6. `trade_status` を `OPEN` に変更する。
7. 実行者に応じて、購入者ページ、出品者取引詳細、管理者商品一覧のいずれかへ遷移する。

## 12. 取引完了

### 12.1 概要

受け渡し完了後、商品を取引完了状態にする。

### 12.2 実行可能ユーザー

- 出品者
- 購入者
- 管理者

### 12.3 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. 実行者が関係者でない場合は403とする。
4. `trade_status` が `LOCKED` でない場合はエラーにする。
5. `trade_status` を `CLOSED` に変更する。
6. 実行者に応じて、購入者取引詳細、出品者取引詳細、管理者商品一覧のいずれかへ遷移する。

## 13. 商品コメント

### 13.1 概要

購入前の質問や補足説明として、商品詳細画面に公開コメントを投稿する。

### 13.2 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. ログインしていない場合はログイン画面へ遷移する。
4. 商品が禁止表示または論理削除済みの場合はエラーにする。
5. コメント本文の必須チェックを行う。
6. `message_type = COMMENT`、`receiver_id = NULL` で `messages` に登録する。
7. 商品詳細画面へ遷移する。

## 14. 取引メッセージ

### 14.1 概要

購入後の受け渡し調整のため、出品者と購入者が非公開でメッセージを送る。購入者は購入者取引詳細、出品者は出品者取引詳細から投稿する。表示する画面は分けるが、同じ商品取引に紐づく1つのメッセージスレッドとして扱う。

### 14.2 処理手順

1. 商品IDで商品を取得する。
2. 商品が存在しない場合は404とする。
3. `trade_status` が `LOCKED` または `CLOSED` であることを確認する。
4. 実行者が出品者、購入者、管理者のいずれかであることを確認する。
5. メッセージ本文の必須チェックを行う。
6. 送信者が出品者なら受信者を購入者にする。
7. 送信者が購入者なら受信者を出品者にする。
8. 管理者送信の場合は画面で指定された受信者を設定する。
9. `message_type = TRANSACTION` で `messages` に登録する。
10. 実行元の購入者取引詳細または出品者取引詳細へ遷移する。

### 14.3 表示取得

1. 商品IDで商品を取得する。
2. `trade_status` が `LOCKED` または `CLOSED` であることを確認する。
3. 実行者が出品者、購入者、管理者のいずれかであることを確認する。
4. 一般学生の場合は、対象商品の現在の `seller_id` と `buyer_id` の組み合わせに一致する `TRANSACTION` メッセージだけを取得する。
5. 管理者の場合は、必要に応じて全ての `TRANSACTION` メッセージを確認できる。
6. `created_at ASC` で画面へ返す。

## 15. マイページ・購入者ページ・出品者ページ

### 15.1 概要

マイページは、購入者ページと出品者ページへの入口を表示する。購入者ページでは自分が購入者になっている取引を確認し、出品者ページでは自分が出品した商品と成立済み取引を確認する。

### 15.2 表示内容

| 画面 | 条件 | 主な表示 |
|---|---|---|
| マイページ | ログインユーザー | 購入者ページへの導線、出品者ページへの導線、進行中取引のサマリー |
| 購入者ページ | `buyer_id = ログインユーザーID` | 購入した商品、出品者、取引ステータス、購入者取引詳細への導線 |
| 出品者ページ | `seller_id = ログインユーザーID` | 自分の出品商品、購入者（成立済み取引のみ）、取引ステータス、出品者取引詳細への導線 |

### 15.3 取引詳細

| 画面 | 権限 | 表示内容 |
|---|---|---|
| 購入者取引詳細 | `buyer_id = ログインユーザーID` または管理者 | 商品概要、出品者、取引ステータス、取引メッセージ、キャンセル、完了 |
| 出品者取引詳細 | `seller_id = ログインユーザーID` または管理者 | 商品概要、購入者、取引ステータス、取引メッセージ、キャンセル、完了 |

購入者取引詳細と出品者取引詳細は別URLにする。利用者の役割に合わせて表示項目と戻り先を変えるためであり、メッセージデータは共通の `messages` を参照する。

取引詳細は `trade_status = LOCKED` または `CLOSED` の商品だけ表示する。

## 16. 管理者商品管理

### 16.1 概要

管理者が全商品を確認し、不適切な商品を禁止表示にする。

### 16.2 処理手順

1. 管理者権限を確認する。
2. 商品一覧をステータス別に取得する。
3. 禁止表示操作時は `moderation_status = PROHIBITED` に更新する。
4. 禁止解除操作時は `moderation_status = ACTIVE` に更新する。
5. 管理者商品一覧へ戻る。

## 17. 管理者カテゴリ管理

### 17.1 概要

管理者がカテゴリを追加・編集・削除する。

### 17.2 処理手順

1. 管理者権限を確認する。
2. カテゴリ名の必須チェックを行う。
3. カテゴリ名の重複を確認する。
4. 追加または更新を行う。
5. 削除時は、そのカテゴリに商品が存在しない場合のみ削除する。
6. 管理者カテゴリ画面へ戻る。

## 18. 商品画像表示

### 18.1 概要

DB に保存された商品画像を HTTP レスポンスとして返す。

### 18.2 処理手順

1. 商品IDと画像IDで `product_images` を取得する。
2. 対応する画像が存在しない場合は404とする。
3. 商品が禁止表示または論理削除済みの場合、一般ユーザーには404とする。
4. `content_type` をレスポンスヘッダーに設定する。
5. `image_data` をレスポンスボディとして返す。

## 19. テスト観点

| 機能 | 観点 |
|---|---|
| ユーザー登録 | 重複学生番号、必須チェック、パスワードハッシュ化 |
| 商品出品 | 価格0円、負の価格、画像形式、画像サイズ、画像枚数 |
| 購入申し込み | 自分の商品購入不可、二重購入防止、`OPEN` 以外は購入不可 |
| 取引キャンセル | `LOCKED` のみキャンセル可能、`buyer_id` がNULLに戻る |
| 取引完了 | `LOCKED` のみ完了可能、`CLOSED` 後は再出品不可 |
| メッセージ | 公開コメントと取引メッセージの表示範囲 |
| 管理者 | 学生が管理者URLへアクセスできないこと |
